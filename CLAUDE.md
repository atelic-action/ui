# CLAUDE.md

Conventions for `@atelic-action/ui`, the shared chrome and base styles the Atelic templates install. Installing, importing, and releasing live in [README.md](README.md).

- **`src/gate/`, `src/vite/`, `src/artifact/readers.ts`, and `src/routing/basePath.ts` are the built corner.** Vercel runs a function's and a middleware's package imports as shipped, by Node's own ESM rules, and compiles nothing inside `node_modules` (proven on a preview, ATE-641), so the gate's exports point at `dist/gate/` (with the plain helpers it imports from `src/lib/`, emitted beside it to `dist/lib/`), which `bun run build` emits and `prepack` runs before every publish. Everything in `src/gate/` is plain TypeScript with no JSX and no React, touching nothing a function or the middleware runtime lacks (the fetch standard and Web Crypto, never `window` or `document`), and its relative imports carry `.js`, which `tsconfig.server.json` enforces under NodeNext. A gate component that renders (the login form, the watermark) is ordinary source and lives with the components, never here. `src/vite/` joins the corner for the same reason from the other side: a site's `vite.config.ts` imports the plugin from `node_modules`, where Node runs no TypeScript, so its export points at `dist/vite/` and it keeps to the same rules. `src/artifact/readers.ts` is the one file of the artifact entry built too (`@atelic-action/ui/artifact/readers`), since a site's browser tests import it under Node, and `src/routing/basePath.ts` the one of the routing entry (`@atelic-action/ui/routing/base-path`), for the same tests. A built entry never holds a React context: a built copy beside the source one is a second context that the source components never read, so the provider stays source.
- **A command finds the site from the working directory.** The files in `src/scripts/` and `bin/` run inside a site's `node_modules`, so nothing of the site's is ever found relative to the file itself (`import.meta.dir`, `import.meta.url`, `$0`): the site's config, `public/`, and `dist/client` resolve against `process.cwd()`. They run under `bun` as source and stay out of the built corner, except the sealing command, which is plain `.mjs` because `node` runs it as shipped. Each file in `bin/` is executable and opens on a shebang; `tst/bin/bin.test.ts` enforces both.
- **Relative imports only.** No `@/` aliases: consumers compile this source with their own Vite, which resolves none of ours.
- **No router imports.** The package runs under TanStack Start prerender and later in a client SPA, so take the current path as a prop. `src/routing/` builds plain option objects for a site to pass its router and imports no router itself.
- **SSR safe.** Every component prerenders. Never touch `window`, `document`, or `localStorage` during render or at module scope, only inside effects and handlers; module scope browser access breaks a site's build.
- **Acronyms stay fully capitalized** in the code names the package mints: components, props, types, and variables (`StickyCTABar`, `primaryCTA`). CSS classes and file names stay kebab lowercase (`.nav-cta`, `sticky-cta-bar.test.tsx`). A name mirroring a DOM attribute keeps the web's spelling (`id`, `ariaLabel`).
- **CSS lives inside `@layer atelic-ui`**, reads the theme tokens, and defines no theme values; `theme.css` stays in each site. Every rule in every sheet is scoped under `.atelic-ui`, the one root class a consumer wears; what a consumer gets is decided by the sheets it imports, never by a second class, so the page components work in an app that wears `.atelic-ui` and imports none of the site base. A token whose name an app's own stack already uses for something else is read through a `--ui-` name with the plain one as its fallback (`--ui-primary`, `--ui-card`). The one exception is the tone palette (`--tone-good` and its kin in `styles/components.css`): good, a warning, and broken read green, amber, and red whatever the brand is, and a site's theme may still restate them.
- **`src/app/` is the app shell, and the one corner that imports a router and is styled with Tailwind** (ATE-643, 1.0.0): an app is built on TanStack Router and Tailwind, so the shell's components use both, and `styles/app.css` is Tailwind source that an app imports inside its own Tailwind entry, outside the `atelic-ui` layer. It reads nothing from the app's files: the app's facts arrive through `AppProvider` (`config`, `nav`) and a `Register` augmentation (the user type), and the code that runs outside React reads the config through `getAppConfig()`. Never read `import.meta.env` there; the app resolves its environment and passes the result in. Its tests live in `tst/app/` on the fixture app in `tst/app/fixtures.ts`.
- **Layout by kind:** `src/chrome/`, `src/components/` for page scale components, `src/primitives/` for the small pieces a page is set in, `src/routing/` for router options, `src/email/`, `src/tokens/`, `src/hooks/`, `src/styles/`, `src/gate/` for the access gate's server side, `src/artifact/` for the pieces an artifact document is built from (the grade chip, the sign off, the shot, the paragraph helpers) and the site around it (the shell, the config, the head, the error boundary, and the reader helpers), `src/vite/` for the Vite configuration and plugin a site's config imports (built, with the gate), `src/scripts/` for the logic of the commands a site calls by name (the build guard, the health stamp, the link and wall checks, the reader link, the static server, the sealing), `src/lib/` for internal helpers, `src/types.ts`. `bin/`, beside `src/`, holds the entry file of each command in the `package.json` `bin` map: it reads the command line, calls a function in `src/scripts/`, and holds no logic of its own. Tests live in `tst/`.
- **The composed documents live in `@atelic-action/artifact`, never here** (ATE-671, 2.0.0). The writeup, the read, the monthly page, the note, and the sealed document, with their stylesheet, moved to that package, which depends on this one for its pieces. A piece more than one document wears is exported from the artifact entry and styled in `styles/artifact.css`, unless a component outside that entry wears it too: then its rules sit in that component's sheet, since an app may load that sheet alone (the grade chip's rules are in `styles/components.css`, because `ReportCard` wears it). A whole document, or a rule only one document uses, goes to that repo.
- **Email components are born inline:** tables for layout, inline style objects, literal palette values off the theme context, no CSS and no `className`. That is what lets them render in a mail client and mount on a web page alike. React Email is deliberately deferred until the first client facing email, since nothing here needs it and adding it later is additive (decided 2026-09-21).
- **No emoji in `src/`.** Write a pictograph the copy needs as an escape (`\u{1F49A}`); `tst/no-emoji.test.ts` enforces it.
- **The gallery** (`gallery/`, served at `ui.atelic.me`) shows everything the package exports that draws, from the repo's own source; a new component gets its gallery section in the same change, in a group file beside `Gallery.tsx` built from the pieces in `gallery/parts.tsx`, and a new export gets its row in the README's Component Index. It is outside `src/`, so it never publishes and never needs a version bump. See [README.md](README.md#the-gallery).
- **This repo is public and publishes to public npm, so grep before the first push of any branch that moves or copies code in from another repo.** The templates and the artifacts are private, and their comments and test fixtures name real people. Sweep the added files for every email address (keep `example.com` style ones and `matt@atelic.me`), every `http(s)://` host (keep `atelic.me`, `summit.atelic.me`, `example.com`), and every client short name (the folder names in `artifacts`), and replace anything real with an example. A push here is publication: amending afterward does not unpublish, since the old commit stays fetchable by hash and a force push shows in the PR timeline (ATE-641, 2026-10-08, when a real contact's address in a component comment reached a PR branch). Put the same check in any builder or lander brief for this repo.
- **Semver:** patch for a fix, minor for a new component or prop, major for a breaking prop or class rename. Every consumer is internal, so a breaking change ships as a major with no shim and every consumer moves forward in the same pass (`~/Eudaimonia/Craft/Development/README.md`, Breaking Changes).
- **Gates:** `bun run lint`, `bun run typecheck`, `bun run test:run`, `bun run build`, `bun run build:smoke`, and `bun run gallery:build`, all green before a merge.

## Component Rules

The rules the sections, primitives, and chrome were built to, moved here from template-marketing's `src/components/CLAUDE.md` when the components did (ATE-643): a change to a component is made in this package, so these govern it. The bullets above already cover the router, SSR safety, acronyms, the layer and tokens, and emoji; these are the rest.

**The prime directive: a component never contains site copy, brand values, or business facts.** Content arrives through props, colors through the theme tokens, identity through `SiteConfig`. If building a site requires editing a component, the component's API is wrong: widen the API here, never fork the component in a site. That covers the copy nobody sees. An accessible name saying what the two halves of a comparison are is site copy in a component, and the copy most likely to rot, because nothing on screen contradicts it once the page changes: `RevealSlider` once announced "the current site and the rebuild" on every page that used it. An accessible name takes a prop with a neutral default (`ariaLabel`), exactly like visible copy.

1. **Compose before creating.** Most new sections are `SplitSection`, `SectionHeading`, and primitives in a trench coat. Create a component only when a pattern has real behavior of its own or appears on more than one site, and name it with the industry's words (hero, eyebrow, marquee, NAP).
2. **A component's styles go in the package sheet for its kind** (`sections.css` for a section), never in a stylesheet the component imports. Vite splits a stylesheet a component imports into that route's chunk, so a shared class there silently vanishes on pages that do not import the component, and only in a production build; and with nothing imported from a component, `marketingConfig` and `artifactConfig` leave CSS code splitting on. A class used across a site's routes that no component owns lives in the site's `src/styles/patterns.css`.
3. **Tokens only:** `var(--primary)`, never `#4d5c05`. A design that needs a color the tokens cannot express gets a new semantic token in the theme contract, documented where the tokens are, never a literal in a sheet.
4. **Watch specificity across the layer.** Every package sheet sits in `@layer atelic-ui`, so any unlayered rule a site writes beats a component's rule with no extra specificity, and an unscoped site class wins over the base element rules (`.atelic-ui h1`, `.atelic-ui p`). It cuts both ways: a site rule that only ever lost to a component's starts winning when the component moves into the layer, so check it against the page.
5. **Zero the `min-width` chain around wide content.** Grid and flex items default to `min-width: auto`, so one unbreakable child (a `pre` line, a long URL) forces every ancestor track wider than the viewport and the page scrolls sideways, on phones only, where nobody at a desk notices. Every track that can hold such content gets `min-width: 0` at every level of the chain, and the wide content scrolls inside its own box (`overflow-x: auto`). Caught by Nick Titus on the DCTC audit page, 2026-07-23.
6. **A side by side comparison keeps its shape on a phone.** Stacking a comparison destroys it: halves that no longer sit beside each other are two lists, and the reader has to hold one in their head to read the other. Give the table a `min-width` floor, size the halves with `table-layout: fixed` so they stay equal whichever holds more words, and let it scroll sideways inside its own `overflow-x: auto` box. Read it beside rule 5: there the width is an accident to contain, here it is the point (`ComparisonTable`, 2026-08-18).
7. **Never style bare elements in a container that can hold a `.btn`.** A context rule such as `.mobile-menu a` outranks the button primitives and corrupts any call to action placed inside (it once bled the menu's `space-between` flex and zero padding into the booking button). Give the container's own links a class (`.mm-link`) and style that; a button renders the same everywhere.
8. **Icons come from `lucide-react`,** never emoji, dingbats, or hand drawn SVGs, so they take the brand's color tokens and render the same on every platform. A decorative icon gets `aria-hidden`, with the name on the control. Typographic copy glyphs such as → and ↓ stay legal.
9. **State survives a render.** Anything an observer or an effect toggles lives in React state, never in a class added imperatively: a render of a stateful child wipes a class only the DOM knew about (that killed the old scroll reveal system).
10. **Placeholders are first class.** A media component takes a `placeholder` shot brief and renders a labeled block, and `Hero` falls back to a token gradient, since a client site launches before its photography exists. A new media component does the same.
11. **A placeholder pair is not a matched pair.** In a component whose whole behavior is the difference between two frames, two identical blocks read as a broken control: the divider drags and nothing changes. Give each side its own tone and its own brief, the way `RevealSlider` renders the before in the inset well and the after in the primary tint, each hatched in its own color, and set each brief against its own outer edge so the stacked, clipped layers never print one brief over the other (2026-08-18).
12. **A link earns `target="_blank"` only through `newTabProps(href, flag)`** (`src/lib/newTabProps.ts`, exported from `@atelic-action/ui/artifact`), and a protocol link never gets it: a `mailto:` or `tel:` in a new tab leaves a dead blank tab on a desktop and breaks the handler on a phone, whatever a config's `external` or `newTab` flag says. Never spread a hand written `{ target: "_blank" }` in a component (atelic.me's mailto call to action, 2026-08-28).
13. **The accessibility floor:** semantic elements, `aria-expanded` on a disclosure's control, an accessible name on every icon button, visible focus states, and `prefers-reduced-motion` respected in any animation. A body a disclosure hides but keeps in the HTML is `inert` while closed, so its links leave the tab order.
14. **A status notice that updates is a plain `<div>`,** never `<output>` or `role="status"`, which both make a polite live region, so a notice that refreshes often (a progress line every two seconds) is announced again on every tick; `AppPageToolbar`'s `notice` is one. Keep `<output>` or an explicit `aria-live` for a one shot status. Biome's `useSemanticElements` pushes `<div role="status">` toward `<output>`, right for the one shot and wrong for the ticking notice; a `<div>` with no role satisfies it either way. (From template-application's retired `src/shared/components/CLAUDE.md`.)
15. **A dark branded client inverts the assumptions about `--surface`.** Several surfaces mix their light from `--surface`: the footer band's text neutrals, the dark navbar's text, the mobile menu's link color. On a theme whose `--surface` is near black those vanish into the band. Until the tokens grow an explicit on dark axis, a dark client's theme derives them again from its `--ink`; the Crema build's `theme.css` carries the working override set (the Crema replatform, 2026-07-23).
16. **Test behavior, not markup.** A component with real logic (filtering, a state machine, a formatter) gets a test in `tst/`; a site tests only what it owns.
17. **Deliberate non-features:** no scroll reveal or entrance animations (removed by decision; never reintroduce them), and no Tailwind or shadcn outside `src/app/`: everywhere else the token system is the styling system.
