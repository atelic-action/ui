# CLAUDE.md

Conventions for `@atelic-action/ui`, the shared chrome and base styles the Atelic templates install. Installing, importing, and releasing live in [README.md](README.md).

- **`src/gate/`, `src/vite/`, and `src/artifact/readers.ts` are the built corner.** Vercel runs a function's and a middleware's package imports as shipped, by Node's own ESM rules, and compiles nothing inside `node_modules` (proven on a preview, ATE-641), so the gate's exports point at `dist/gate/` (with the plain helpers it imports from `src/lib/`, emitted beside it to `dist/lib/`), which `bun run build` emits and `prepack` runs before every publish. Everything in `src/gate/` is plain TypeScript with no JSX and no React, touching nothing a function or the middleware runtime lacks (the fetch standard and Web Crypto, never `window` or `document`), and its relative imports carry `.js`, which `tsconfig.server.json` enforces under NodeNext. A gate component that renders (the login form, the watermark) is ordinary source and lives with the components, never here. `src/vite/` joins the corner for the same reason from the other side: a site's `vite.config.ts` imports the plugin from `node_modules`, where Node runs no TypeScript, so its export points at `dist/vite/` and it keeps to the same rules. `src/artifact/readers.ts` is the one file of the artifact entry built too (`@atelic-action/ui/artifact/readers`), since a site's browser tests import it under Node.
- **A command finds the site from the working directory.** The files in `src/scripts/` and `bin/` run inside a site's `node_modules`, so nothing of the site's is ever found relative to the file itself (`import.meta.dir`, `import.meta.url`, `$0`): the site's config, `public/`, and `dist/client` resolve against `process.cwd()`. They run under `bun` as source and stay out of the built corner, except the sealing command, which is plain `.mjs` because `node` runs it as shipped. Each file in `bin/` is executable and opens on a shebang; `tst/bin/bin.test.ts` enforces both.
- **Relative imports only.** No `@/` aliases: consumers compile this source with their own Vite, which resolves none of ours.
- **No router imports.** The package runs under TanStack Start prerender and later in a client SPA, so take the current path as a prop. `src/routing/` builds plain option objects for a site to pass its router and imports no router itself.
- **SSR safe.** Never touch `window` or `document` during render, only inside effects and handlers.
- **Acronyms stay fully capitalized** in the code names the package mints: components, props, types, and variables (`StickyCTABar`, `primaryCTA`). CSS classes and file names stay kebab lowercase (`.nav-cta`, `sticky-cta-bar.test.tsx`). A name mirroring a DOM attribute keeps the web's spelling (`id`, `ariaLabel`).
- **CSS lives inside `@layer atelic-ui`**, reads the theme tokens, and defines no theme values; `theme.css` stays in each site. A rule in `styles/components.css` answers to `:is(.mkt, .atelic-ui)`, never `.mkt` alone, so the page components work in an app that wears `.atelic-ui` and none of the site base; the chrome and `base.css` stay `.mkt` only. A token whose name an app's own stack already uses for something else is read through a `--ui-` name with the plain one as its fallback (`--ui-primary`, `--ui-card`). The one exception is the tone palette (`--tone-good` and its kin in `styles/components.css`): good, a warning, and broken read green, amber, and red whatever the brand is, and a site's theme may still restate them.
- **Layout by kind:** `src/chrome/`, `src/components/` for page scale components, `src/primitives/` for the small pieces a page is set in, `src/routing/` for router options, `src/email/`, `src/tokens/`, `src/hooks/`, `src/styles/`, `src/gate/` for the access gate's server side, `src/artifact/` for the artifact documents (the writeup, the monthly page, the sealed document, their shell, config, and reader helpers), `src/vite/` for the Vite configuration and plugin a site's config imports (built, with the gate), `src/scripts/` for the logic of the commands a site calls by name (the build guard, the health stamp, the link and wall checks, the reader link, the static server, the sealing), `src/lib/` for internal helpers, `src/types.ts`. `bin/`, beside `src/`, holds the entry file of each command in the `package.json` `bin` map: it reads the command line, calls a function in `src/scripts/`, and holds no logic of its own. Tests live in `tst/`.
- **Email components are born inline:** tables for layout, inline style objects, literal palette values off the theme context, no CSS and no `className`. That is what lets them render in a mail client and mount on a web page alike. React Email is deliberately deferred until the first client facing email, since nothing here needs it and adding it later is additive (decided 2026-09-21).
- **No emoji in `src/`.** Write a pictograph the copy needs as an escape (`\u{1F49A}`); `tst/no-emoji.test.ts` enforces it.
- **The gallery** (`gallery/`, served at `ui.atelic.me`) shows every page component from the repo's own source; a new page component gets its gallery section in the same change. It is outside `src/`, so it never publishes and never needs a version bump. See [README.md](README.md#the-gallery).
- **Semver:** patch for a fix, minor for a new component or prop, major for a breaking prop or class rename.
- **Gates:** `bun run lint`, `bun run typecheck`, `bun run test:run`, `bun run build`, and `bun run gallery:build`, all green before a merge.
