# design/

The Design System producer: `design/build.ts` turns this package into the files of the Claude Design System artifact, under `design/out/project/` (gitignored), with `publish-plan.json` and `index.proposed.json` beside them. The session publishes; nothing here does, and the live index (`design-system.json`) is never written here.

- **Previews derive from stories and are never authored here.** Each card mounts its component's primary story (the first export of its story file) through `preview.tsx`, with `storybook/test` stubbed (`stubs/`). A card that needs another story, args laid over the story's, or a fixed height gets an entry in `cards.json`, whose schema is the Producer section of `README.md`; fix a poor card there or in the story, never by writing markup.
- **`README.md` is the brand book**, copied to `project/README.md` with a generated Not Synced section appended. It is prose for designers: no dashes in it, and every rule it states must hold in the code.
- **Tokens come from the sheets**: `src/styles/theme.css`, the default density in `base.css`, and `defaults.css`, with each usage from the package README's token tables, else the sheet's comment. A value the format cannot hold is skipped and listed, never approximated.
- **Run** `bun run design:build`, then `bun run design:check` (headless Chromium: fails on a console error, a failed request, or an empty card; writes each card's height; `--shots` saves pictures to `design/out/shots/`).
- **Publishing a sync** is done by the session with the Artifact tool, after `bun run design:build` and `bun run design:check` are green; `design/out/publish-plan.json` names every file, and the artifact's id is kept outside this public repo. Read the artifact by its URL right before publishing, even after reading its files by path, since a publish to a version the session has not read is refused. Publish in batches of at most 255 paths, removals counted, with `root` set to `design/out` and every path under `project/`, keeping a version at 511 files or fewer, and sending the removal batches first; `project/components/index.d.ts` goes with `contentType` `text/plain`, since a `.ts` name is not served on its own. Removals are `null` entries for every live path under `project/` that the plan's `files` does not name, except `project/design-system.json`, which the plan never names and the live artifact must keep, read from the live file listing, which also clears the retired layout. The index, `project/design-system.json`, goes once, as the `file_path` of the last call: the live one read back, `source` removed, `namespace`, `libraries`, `lastChange`, and `"editing": "code"` set, every other key kept, merged from `design/out/index.proposed.json` after the build, and written outside `design/out/project`, which the build empties, so the call names it in `files` as served at `project/design-system.json`, from its absolute path, since a path outside `root` has no served path of its own.
